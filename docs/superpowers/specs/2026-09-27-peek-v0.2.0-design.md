# Peek v0.2.0 — Reliable everywhere

## Goal and scope

Make a single Peek preview dependable across common Node development servers, temporary tunnel interruptions, local-network testing, and Windows process trees. Preserve the v0.1 default: running `peek` in a project with a `dev` script requires no configuration, account, or manually installed `cloudflared`.

This release includes the v0.2 items in `docs/ROADMAP.md`: framework-aware detection; ordered, verified server discovery; blocked-host advice; WebSocket/HMR checks; tunnel reconnection; `--lan`; `--json`; `peek doctor`; Windows discovery and cleanup; and optional `peek.config.ts`. Passwords, local reverse proxy, inspector, and multiple services remain in later roadmap versions.

The work is divided into four implementation areas that share one release gate: server discovery and Windows processes; tunnel monitoring and protocol checks; LAN and output modes; configuration and doctor. Each area has isolated tests and can be reviewed separately within the v0.2 branch.

## Command contract

Existing commands and flags retain their meaning. New forms are:

```text
peek [--lan] [--json] [other options]
peek [options] -- <executable> [arguments...]
peek doctor [--live] [--json]
```

`--lan` and `--provider` cannot be combined: LAN mode does not start a tunnel. `--json` writes only newline-delimited JSON events to standard output, including child output and failures; it disables the QR and human-readable decorations. A stable `schemaVersion: 1` field appears on every event. Human-readable errors continue to use standard error. Explicit command tokens after `--` continue to bypass project discovery, and all processes continue to start from executable-plus-argv arrays without shell evaluation.

An optional project-root `peek.config.ts` exports `defineConfig({ command, port, provider, qr })` as its default value. `command` is a nonempty array of string tokens, such as `['bun', 'run', 'dev']`; no string command or shell syntax is accepted. `port` is an integer from 1 through 65535; `provider` is `cloudflare`; `qr` is a boolean. Unknown keys and invalid values fail before any process starts. CLI flags and the explicit `--` command override config values; config values override automatic project and port detection. The file is trusted project code and is loaded only from the current project root. Its TypeScript loader must support the full Node 22 engine range; a small runtime dependency is acceptable if Node's built-in loader cannot do that. The loader and its reason are documented before addition. Plain `peek` still works without this file.

## Server discovery and process ownership

Framework hints come from local package metadata and documented startup-output patterns for Next.js, Vite, Astro, Nuxt, TanStack Start, Remix/React Router, SvelteKit, and generic Node servers. Hints improve URL extraction and diagnostics; they never authorize a port by themselves. Parsers are separate from the discovery coordinator so new patterns do not change lifecycle rules.

Candidate priority is: CLI `--port`, config `port`, local URLs emitted by the dev process, direct child listeners, descendant-process listeners, then newly opened common ports. Every candidate must accept a TCP connection on loopback. Explicit ports must be free before startup and must belong to the child tree when ownership data is available. Emitted ports must have positive ownership evidence, or be proven newly opened from a pre-start snapshot; a reachable port alone is insufficient. Child and descendant listeners have direct ownership evidence. Common ports must have been closed before startup and newly opened after it. If evidence is unavailable or multiple equally ranked candidates remain, Peek fails with an actionable `--port` suggestion. No fallback may select a port known to belong to another process.

Process-tree inspection is platform-specific behind one injectable interface. Linux uses `/proc`, macOS uses process and socket tooling, and Windows resolves descendants and listening sockets without launching a shell for the dev command. Inspection failure is reported as unavailable evidence, not proof of ownership. Exit, Ctrl+C, and forced shutdown still stop the tunnel before the entire dev process tree. Windows CI exercises process discovery, executable resolution, Ctrl+C, and cleanup with fixture processes.

## Tunnel health and reconnection

The provider contract in `src/tunnel/types.ts` remains the boundary for Cloudflare. After initial connection, a tunnel exit moves Peek to `reconnecting`, marks the old public URL unavailable, and retries only the tunnel. The dev server stays running. Retry delays increase from 1 to 30 seconds, then stay capped at 30 seconds; a failed attempt reports a concise warning. Peek keeps trying until Ctrl+C, the dev server exits, or a nonrecoverable local error occurs. A new valid Quick Tunnel URL emits another `ready` event and replaces the old URL. Cancellation interrupts both connection attempts and retry delays. Cleanup must leave no tunnel child from any attempt.

Once a public URL is available, a bounded HTTP probe looks for known host-rejection responses. A recognized Vite-family rejection recommends `--host-header localhost`, which tells `cloudflared` to send `Host: localhost` to the origin; arbitrary override values are rejected. This is a working remedy for Quick Tunnel hostnames that change on every run. The CLI documents that an application generating absolute URLs from the Host header may behave differently. Unknown responses do not get a speculative fix. For frameworks with a documented HMR WebSocket endpoint, Peek compares local and public upgrade behavior using bounded probes and warns when a local upgrade works but the public one returns a failed upgrade. Network errors are unverified. When no safe endpoint can be identified, it makes no HMR claim. A Vite probe that cannot complete is reported as unverified rather than claiming success or failure. These checks never select or change the server port and never collect source code or environment variables.

## LAN and doctor

`--lan` selects a unique usable private IPv4 address on an active interface, verifies the chosen server also accepts connections through that address, and displays `http://<address>:<verified-port>` with a QR when terminal size allows. Loopback-only binding, no private interface, and ambiguous usable interfaces produce clear remedies. LAN mode never downloads or starts `cloudflared` and never prints a public URL. It still owns and stops the dev server. It does not claim that another device can pass a host firewall.

`peek doctor` checks Node version, project command availability, configuration validity, cached `cloudflared` checksum/status, network reachability, and local port-discovery prerequisites without starting a dev server. It reports pass, warning, or failure for each check and gives a remedy. `peek doctor --live` runs the selected dev command and a temporary tunnel through the same lifecycle, tests port selection, blocked-host behavior, and eligible HMR upgrades, then cleans up both children. Live checks are opt-in because they require the public Cloudflare network. `--json` makes doctor emit the same versioned JSON event format.

## Errors, tests, and release

Errors distinguish startup, detection, tunnel retry, host rejection, HMR warning, LAN selection, configuration, and doctor failures. A warning does not terminate a healthy dev server. The terminal and JSON renderer consume the same typed event stream so both modes report equivalent state. Diagnostics must not include source files or environment-variable values.

Focused unit tests cover framework parsers, discovery priority and ownership, config validation and precedence, LAN address selection, and JSON shape. Integration tests use fake dev servers and fake tunnel processes to verify reconnects, changing URLs, blocked-host and HMR probes, cancellation during retry, `--lan`, doctor cleanup, and no surviving child after failure. Normal CI does not call the public Cloudflare network. The existing Node 22/24 and Linux/macOS/Windows matrix remains the cross-platform gate.
