## Global Constraints

- Keep existing CLI and JSON callbacks, event names, fields, schema version, and ordinary exit mapping. Do not expose internal phase names as JSON state values.
- Provider cleanup waits five seconds gracefully and one second after force. Dev cleanup waits three seconds gracefully and one second after force. Further termination requests force both resources and advance the current graceful wait to its forced wait.
- Preserve the first signal exit code: SIGINT 130, SIGTERM 143. Successful requested live-doctor completion remains 0; otherwise successful completion with cleanup failure uses 1. CLI misuse remains 2; ordinary failure remains 1.
- Keep primary failure and cleanup failure observable. Cleanup must never prevent dev termination or signal-handler removal, and no final cleanup rejection may escape the CLI renderer.
- Reconnect retains the same dev process and verified port. Keep the current delays, retry counter behavior, and retry policy for the later process/reconnect phase.
- Keep Node 22 compatibility, existing provider contract, argv spawning, port verification, package exports, dependencies, binary pins, and checksum policy. Implement no proxy, auth, expiry, or additional provider.
- Normal tests use deterministic local processes and networking. Windows signal-handler invocation and native console delivery must be described separately.
- Follow antislop: concrete names, comments explaining reasons, concise docs, and only measured compatibility claims.

Use this internal API. It is not a package export:

```ts
export type LifecyclePhase =
  | 'idle' | 'starting-server' | 'discovering-server' | 'server-ready'
  | 'tunnel-connecting' | 'ready' | 'reconnecting' | 'stopping' | 'stopped'

export type LifecycleOutcome =
  | { kind: 'completed' }
  | { kind: 'requested' }
  | { kind: 'failed'; error: unknown }

export interface CleanupResult {
  error?: PeekError
}
```

`Lifecycle` exposes `phase`, `outcome`, `signal`, `isStopped`, `wasRequested`,
and the existing `signalExitCode`. `advance(phase)` checks the spec's table.
`stop(outcome?: LifecycleOutcome): Promise<CleanupResult>` always resolves to
a cached result. `setDev(dev): Promise<void>` and
`setProvider(provider): Promise<void>` register synchronously before returning
their normal resolved promises; callers will await them in Task 2. Late
registration awaits bounded cleanup and then rejects with cancellation or an
actionable cleanup error. Registering the same owned object is idempotent;
replacing a different owned object rejects after closing the rejected object.

Define and export the two resource-specific helpers from `cleanup.ts`:

```ts
export function cleanupProvider(
  provider: TunnelProvider,
```

These signatures describe implemented functions, not overload declarations to
copy without bodies. Internally, one bounded-wait helper distinguishes fulfilled,
rejected, timeout, and force-requested outcomes. Attach both promise settlement
handlers before racing; use referenced timers and remove timers/force listeners
in `finally`. On forced wake, leave the graceful budget immediately and apply
the one-second forced wait. A force hook throwing is a cleanup problem, not an
escape from cleanup. Provider rejection still triggers best-effort force when
available. An unconfirmed exit remains a failure even after a force request.

Use minimal adapters such as this dev process; no real process uses fake clocks:

```ts
function deferred<T>() {
  let resolve!: (value: T) => void
  let reject!: (reason: unknown) => void
  const promise = new Promise<T>((yes, no) => { resolve = yes; reject = no })
  return { promise, resolve, reject }
}

it('forces a dev process after its graceful deadline', async () => {
  vi.useFakeTimers()
  try {
    const exit = deferred<ProcessExit>()
    const dev: DevProcess = {
      pid: 123,
      stdout: new PassThrough(),
      stderr: new PassThrough(),
      exit: exit.promise,
      kill: vi.fn(),
    }
    const result = cleanupDev(dev, new AbortController().signal)
    await vi.advanceTimersByTimeAsync(2999)
    expect(dev.kill).toHaveBeenCalledWith('SIGTERM')
    expect(dev.kill).not.toHaveBeenCalledWith('SIGKILL')
    await vi.advanceTimersByTimeAsync(1)
    expect(dev.kill).toHaveBeenCalledWith('SIGKILL')
    await vi.advanceTimersByTimeAsync(1000)
    expect((await result).error?.code).toBe('PROCESS_CLEANUP_ERROR')
    expect(vi.getTimerCount()).toBe(0)
  } finally {
    vi.useRealTimers()
  }
})
```

Cover provider five-plus-one seconds, dev three-plus-one, graceful success,
provider rejection, absent force hook, force hook/kill exceptions, dev exit
rejection, forced wake before either deadline, and observed late rejection.
Assert timer disposal and outcome, not merely calls to a mocked hook.

Use the following result construction policy for multiple cleanup problems:

```ts
function cleanupFailure(errors: readonly PeekError[]): CleanupResult {
  if (errors.length === 0) return {}
  return {
    error: new PeekError(
      'PROCESS_CLEANUP_ERROR',
      errors.map((error) => error.message).join('\n'),
      'Check for remaining dev or tunnel processes before starting Peek again.',
      new AggregateError(errors, 'Preview cleanup failed'),
    ),
  }
}
```

Keep resource-specific messages actionable without dumping argv, environment,
or stacks. Unexpected cleanup exceptions also become a cleanup result. An
async late registration closes its rejected resource using the same helpers;
its caller owns that awaited result even if the original stop already settled.
No late registration may mutate the recorded phase or completed stop result.

Use this replacement catch/finally pattern, retaining the original thrown value:

```ts
catch (error) {
  const cancelled = signal.aborted && (
    error === signal.reason ||
    (lifecycle.wasRequested && error instanceof Error && error.name === 'AbortError')
  )
  if (!cancelled ||
      (error instanceof PeekError && error.code === 'PROCESS_CLEANUP_ERROR')) {
    primary = { error }
  }
} finally {
  previewController?.abort()
  const cleanup = await lifecycle.stop(
    primary ? { kind: 'failed', error: primary.error } : undefined,
  )
  if (primary) throw primary.error
  if (cleanup.error) throw cleanup.error
}
```
