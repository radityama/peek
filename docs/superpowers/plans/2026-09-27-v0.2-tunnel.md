# Peek v0.2 Tunnel Reliability Implementation Plan

> **For agentic workers:** Implement the checkbox steps in order. Use fake tunnel processes in CI; run the public tunnel manually only for the release gate.

**Goal:** Keep a dev server alive across tunnel drops and report host/HMR failures accurately.

**Architecture:** `src/core/reconnect.ts` owns retry timing while `runPeek` owns lifecycle. `src/core/preview-checks.ts` performs bounded HTTP and WebSocket probes without selecting ports. The Cloudflare provider remains behind `src/tunnel/types.ts`.

**Tech Stack:** Node.js 22+ networking APIs, strict TypeScript, Vitest, existing Cloudflare provider.

---

### Task 1: Tunnel reconnection

**Files:** Create `src/core/reconnect.ts`; modify `src/core/run.ts`, `src/tunnel/cloudflare.ts`, `src/tunnel/types.ts`, `src/ui/output.ts`; test `tests/integration/lifecycle.test.ts`, `tests/unit/cloudflare.test.ts`.

- [ ] Add fake-tunnel integration cases for a dropped tunnel, a failed retry, a recovered new URL, a dev exit during backoff, and Ctrl+C during connection. Run the focused tests and confirm the new cases fail.
- [ ] Implement abortable retry delays of 1, 2, 4, 8, 16, then 30 seconds, capped at 30. Keep the dev process intact and expose `reconnecting`, `retry`, and renewed `ready` events.
- [ ] Ensure `CloudflareProvider.connect` resets per-attempt diagnostics and child state; `disconnect` stops the current child and waits for exit. Run the focused tests and typecheck.
- [ ] Commit the focused files as `feat: reconnect dropped Quick Tunnels`.

### Task 2: Public preview checks

**Files:** Create `src/core/preview-checks.ts`; modify `src/core/run.ts`, `src/ui/output.ts`, `src/utils/errors.ts`; test `tests/unit/preview-checks.test.ts`, `tests/integration/lifecycle.test.ts`.

- [ ] Write HTTP fixture tests for recognized Vite and other documented host-rejection responses, generic response, timeout, and abort. Run focused tests and confirm failures.
- [ ] Implement bounded GET probes with framework-specific remedies only for recognized signatures. Show a warning and unhealthy state without altering port selection.
- [ ] Write WebSocket upgrade fixture tests for local success/public failure, both success, unknown endpoint, timeout, and abort. Run focused tests and confirm failures.
- [ ] Implement eligible framework-specific HMR probes. Report unknown as unverified; warn only when local upgrade works and public upgrade fails.
- [ ] Run `pnpm test tests/unit/preview-checks.test.ts tests/integration/lifecycle.test.ts`, `pnpm typecheck`, then commit as `feat: diagnose preview host and HMR failures`.
