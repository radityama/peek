# Peek v0.2.1 Update Notification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Inform preview users of a newer npm release without delaying Peek or changing its machine-readable output.

**Architecture:** A standalone update module owns the npm request, semver decision, and 24-hour user cache. The CLI starts it without awaiting and hands its result to a small notice coordinator that waits for the first preview URL. Terminal rendering stays in `TerminalOutput`; JSON mode never starts the checker.

**Tech Stack:** Node.js 22+ built-in fetch and async filesystem, TypeScript, `semver`, Citty, Vitest.

## File map

| File | Responsibility |
| --- | --- |
| `src/update/cache.ts` | Validate and atomically write `~/.peek/update-check.json`; claim expired checks across processes. |
| `src/update/check.ts` | Fetch one npm version with a deadline, compare semver, and swallow update failures. |
| `src/update/notice.ts` | Buffer a result until ready and print it at most once. |

| `src/ui/output.ts` | Human notice format. |
| `tests/unit/update-cache.test.ts` | Cache TTL, failed cooldown, corruption, and claim behavior. |

| `tests/unit/update-notice.test.ts` | Readiness ordering and single display. |
| `tests/integration/cli.test.ts` | CLI version and JSON smoke coverage. |
| `tests/integration/lifecycle.test.ts` | Preview readiness while a registry response remains pending. |
| `package.json`, `pnpm-lock.yaml`, `CHANGELOG.md`, `README.md`, `docs/ARCHITECTURE.md` | Dependency, version, and user/contributor documentation. |

### Task 1: Cache and version decision

**Files:** Create `src/update/cache.ts`, `src/update/check.ts`, `tests/unit/update-cache.test.ts`, `tests/unit/update-check.test.ts`; modify `package.json`, `pnpm-lock.yaml`.

- [ ] **Step 1: Add `semver` and its types.** Run `pnpm add semver` and `pnpm add -D @types/semver`. Expect package and lockfile changes; use `gt`, `valid`, and `prerelease` from this package.
- [ ] **Step 2: Write failing cache tests.** With `mkdtemp(join(tmpdir(), 'peek-update-'))`, verify `readCache` returns `undefined` for absent/corrupt files, a successful record for `{ checkedAt: now, latestVersion: '0.2.1' }`, and a failed record for `{ checkedAt: now }`. Verify `claimCheck` allows one claimant, rejects another, and releases the claim. Run `pnpm exec vitest run tests/unit/update-cache.test.ts`; expect missing exports.
- [ ] **Step 3: Implement cache.** Export `readCache(path): Promise<UpdateRecord | undefined>`, `writeCache(path, record): Promise<void>`, and `claimCheck(path): Promise<(() => Promise<void>) | undefined>`. Use `~/.peek/update-check.json` as the production path. `UpdateRecord` is `{ checkedAt: number; latestVersion?: string }`. Validate numeric timestamps and semver strings; use `fs.open(lockPath, 'wx', 0o600)`, atomic temporary-file rename, and remove a stale lock older than ten seconds. Identify each lock claimant so its release cannot remove a replacement lock. Re-read the cache after claiming to avoid duplicate checks. Run the focused cache test; expect PASS.
- [ ] **Step 4: Write failing checker tests.** Call `checkForUpdate({ currentVersion: '0.2.0', cachePath, now, requestLatest })` with injected responses. Assert equal/older versions return `undefined`, `0.2.1` returns `{ current: '0.2.0', latest: '0.2.1' }`, a stable install ignores `0.3.0-beta.1`, and a prerelease install compares normally. Assert success and failure both suppress further calls for 24 hours, then refresh. Assert registry rejection and timeout return `undefined`. Run `pnpm exec vitest run tests/unit/update-check.test.ts`; expect missing export.
- [ ] **Step 5: Implement checker.** Export `checkForUpdate` with injected `now`, `cachePath`, `requestLatest`, `signal`, and `timeoutMs`; provide defaults for production. Use a fixed `https://registry.npmjs.org/-/package/@radityprtama%2fpeek/dist-tags` GET, `AbortSignal.any` with `AbortSignal.timeout(2000)`, `response.ok`, and JSON `latest` validation. Before requesting, write `{ checkedAt: now }` so a failure has a cooldown; overwrite with the validated latest version on success. Catch all update/cache errors and return `undefined`. Release the claim in `finally`. Run the focused checker and cache tests; expect PASS.
- [ ] **Step 6: Commit.** Run `pnpm typecheck` and commit these files as `feat: add cached update check`.
